# YOLO11 Pilot Workspace — `data/annotations/yolo11_pilot/`

Status: ready for CVAT upload · Built by `src/annotation/build_pilot.py` (deterministic, rerunnable; refuses to overwrite existing files) · Policy: `docs/YOLO11_ANNOTATION_POLICY.md` · CVAT steps: `docs/YOLO11_CVAT_WORKFLOW.md` · Validator: `src/annotation/validate_labels.py`

This directory is the working folder for the 160-image bounding-box annotation pilot. **No labels exist yet**: the pilot images were copied and verified, but every box must be drawn by a human in CVAT. Nothing in this folder was generated by a model, and no bounding-box coordinates have been invented.

## 1. Contents

| Path | What it is |
|---|---|
| `images/` | 160 pilot JPEGs (~360x363), byte-identical copies (sha256-verified) of their source rows in `outputs/reports/splits.csv`. This is the folder to upload to CVAT. |
| `pilot_manifest.csv` | One row per image: `pilot_index, class_name, class_id, split, filename, source_rel_path, workspace_image_path, width, height, sha256`. The image-level `class_name`/`class_id` are a prior for the annotator, **not** box ground truth (policy §1). `split` preserves the original train/val/test assignment (policy §10). |
| `pilot_selection_summary.json` | Selection provenance: rule, per-class/split counts (20/class; 112 train / 24 val / 24 test), 32 duplicate-hash rows excluded, and the verification flags that were all `true` at build time. |
| `labels/` | **Created when CVAT labels are exported** (one `<stem>.txt` per image, YOLO detection format). Does not exist yet; do not hand-create it except for validation tests. |
| `review_log.csv` | **Created by the annotator** during/after the CVAT pass (see §3). Free-text review trail referenced by the policy. |

## 2. Selection facts (from `pilot_selection_summary.json`)

- 160 images, 20 per class across all 8 classes (basophil, eosinophil, erythroblast, ig, lymphocyte, monocyte, neutrophil, platelet).
- Stratified from the leakage-safe `outputs/reports/splits.csv`: train 14 / val 3 / test 3 per class. Splits must never change after labeling (policy §10).
- Deterministic selection (sorted strata, evenly spaced indices); all duplicate sha256 rows were excluded from the pool, so the pilot contains no near-duplicate leakage.

## 3. Review log — `review_log.csv`

Create this file in the workspace when annotation starts; it is the audit trail the policy repeatedly points to. Header:

```csv
filename,pilot_index,issue,detail,annotator,date
```

- `issue` is one of: `truncated`, `ambiguous_class`, `ambiguous_extent`, `empty_unverified`, `other`.
  - `truncated` — cell cut by an image edge; required by policy §2.4 / §7 (also tick the `truncated` attribute on the CVAT shape).
  - `ambiguous_class` / `ambiguous_extent` — every shape annotated `confidence = medium|low`, and every object left unlabeled with a frame comment (policy §5).
  - `empty_unverified` — label file intentionally left empty; mandatory for any `unverified_empty` image (policy §9). Empty is **never** a verified negative.
- One row per decision; `detail` explains the object/frame location in words. This log plus the exported labels feed the ambiguity statistics that decide whether a second annotator pass is needed before scaling (policy §5).

## 4. Working order

1. Read `docs/YOLO11_ANNOTATION_POLICY.md` (all 10 sections) before drawing the first box.
2. Follow `docs/YOLO11_CVAT_WORKFLOW.md` to create the CVAT project/task from `images/`, with the exact 8 labels and the two attributes.
3. Annotate; maintain `review_log.csv` as you go.
4. Export YOLO format and place the label files in `labels/` (workflow doc §6–7).
5. Validate: `.venv/Scripts/python.exe -m src.annotation.validate_labels` — exit code 0 required; `invalid` lines must be fixed in CVAT and re-exported, not patched by hand in the `.txt` files.
6. Record validator output (counts of `ok` / `unverified_empty` / `pending_missing` / `invalid`) in the pilot report.

## 5. Invariants

- All 160 images and this manifest were verified at build time (sha256 + dimensions); re-verify before export if any file is moved.
- The class IDs here and everywhere else come from `outputs/reports/class_to_idx.json` (0 basophil … 7 platelet) and must not be renumbered.
- No model-generated or auto-pseudo labels are ever written into `labels/`; only CVAT exports go there.
- The full 17k-image dataset stays where it is — this folder holds only the 160 pilot copies.
